## 1. 产品概述与定位

### 1.1 一句话产品定义

**「伴」是一款 AI 原生的社交+管家应用：用最简洁的通讯连接人，用最懂你的 AI 管理生活。** 它不是"带 AI 功能的微信"，而是"以 AI 为底座的个人生活操作系统"——通讯、提醒、圈子都只是 AI 调度的前台界面。

### 1.2 三驾马车

| 支柱              | 角色 | 说明                                               |
| --------------- | -- | ------------------------------------------------ |
| 🔹 **简洁通讯（守）**  | 防守 | 纯文字/语音对话，无广告、无信息流、无商城。对标微信做"减法"，抢夺对臃肿生态疲劳的用户     |
| 🔹 **生活管家（攻）**  | 进攻 | 聚合账单、出行、消费、工作事务，把碎片化的数字生活统一成一条"今日时间线"，AI 主动提醒与规划 |
| 🔹 **AI 分身（魂）** | 灵魂 | 全方位了解用户的 AI 角色（管家/秘书/分身），越用越懂你，形成数据飞轮与迁移成本       |

> **核心差异化逻辑：** 微信赢在"连接人"，但它永远不会变成你的生活管家（商业模型靠广告与流量分发）；ChatGPT 赢在"智能"，但它没有你的生活数据，只能你问一句它答一句。「伴」的机会在两者之间的空白带：**有生活数据的 AI + 无商业噪音的通讯**。

### 1.3 命名建议（备选）

| 名称              | 寓意                  | 备注            |
| --------------- | ------------------- | ------------- |
| **伴 / Bandful** | 陪伴、伙伴、管家随侍在侧        | 首选，单字易记，情感温度高 |
| 小满              | "小满即安"，不过度、不臃肿的产品哲学 | 契合"反微信臃肿"定位   |
| 知吾              | 知我者，AI 也            | 强调画像与懂你的能力    |

## 2. 社会环境洞察 —— 为什么是现在

### 📱 趋势一：超级 App 疲劳，"反臃肿"情绪蔓延

微信已从通讯工具演变为"操作系统级"商业综合体：视频号、直播、小程序、搜一搜广告、公众号信息流。年轻用户群体中出现明显的"数字极简主义"倾向——关掉朋友圈、折叠群聊、寻找纯净通讯工具。海外市场已验证该趋势（如极简社交 App 的多次走红），**国内尚无一个"克制的、无广告的"主流替代品**。

### 🤖 趋势二：大模型 Agent 能力成熟，个人 AI 管家具备技术可行性

2025–2026 年，大模型的长记忆、工具调用（Function Calling）、多模态理解能力已经商用化，推理成本两年内下降超 90%。"个人 Agent"从概念变为可交付产品。**谁先积累用户的个人上下文数据，谁的 AI 就越懂用户**，这是天然的先发壁垒。

### 🏠 趋势三：独居经济与"时间贫困"的新中产

中国独居家庭户已超 1.25 亿，一人食、一人行成为常态；一二线城市白领普遍"时间贫困"——账单忘缴、行程混乱、会议冲突是高频痛点。他们没有秘书，但**买得起 20 元/月的 AI 秘书**。同时银发群体触网率持续提升，语音优先的 AI 交互对老年人极度友好。

### 🧩 趋势四：数字生活碎片化，缺乏统一的"生活仪表盘"

一个普通用户的数字生活散落在 30+ App：信用卡账单在银行 App、物流在电商 App、行程在携程/12306、外卖在美团/饿了么、会议在公司 OA。**没有任何一个入口能回答"我今天要做什么"这个简单问题**。聚合的价值随碎片化程度加深而放大。

> ⚠️ **监管环境的另一面：**《个人信息保护法》《生成式人工智能服务管理暂行办法》提高了数据与 AI 产品的合规门槛，对小团队是成本，但对"以隐私为卖点"的产品是**护城河**——大厂的广告商业模式反而使其难以承诺"绝不用你的数据变现"。

## 3. 目标市场与用户画像

### 3.1 市场分层

| 关键数字         | 含义                     |
| ------------ | ---------------------- |
| **1.25 亿+**  | 中国独居家庭户（情感+管家需求基本盘）    |
| **~2.4 亿**   | 一二线 25–40 岁新中产（核心付费人群） |
| **¥20–30/月** | AI 订阅心理价位（参照视频会员）      |
| **2.8 亿+**   | 60 岁以上人口（银发语音交互延展市场）   |

| 层级              | 人群                 | 核心诉求                      | 对应模块            |
| --------------- | ------------------ | ------------------------- | --------------- |
| **核心层（MVP 主攻）** | 25–40 岁一二线城市白领/新中产 | 效率焦虑：账单、行程、会议统一管理；对微信臃肿疲劳 | 提醒 + AI + 对话    |
| **增长层（V2 扩展）**  | 企业中高层 + 其秘书/行政     | 差旅行程、会议接待有人代录，自己只看"今日时间线" | 提醒（秘书后台）+ AI    |
| **延展层（V3 探索）**  | 家庭主理人、银发群体         | 家庭账单代缴、子女远程关怀、语音交互        | 圈子（家庭圈）+ AI（语音） |

### 3.2 典型用户画像（Persona）

#### 👨‍💼 画像 A：陈默，32 岁，互联网公司中层

- **痛点：** 每月 6 张信用卡 + 房贷 + 车贷，还款日靠脑子记；出差频繁，机票酒店行程散落在 5 个 App；微信群 200+，真正重要的消息被淹没。
- **使用场景：** 早上 8 点 AI 推送今日时间线（10 点会议、下午 3 点高铁、招行信用卡后天到期）；高铁上语音让 AI 把周日聚会安排进日程并通知朋友。
- **付费意愿：** 高。愿为"不漏事"付费 30 元/月。

#### 👩‍💼 画像 B：林秘书，28 岁，董事长行政助理

- **痛点：** 老板的出差、会议、接待安排靠微信一条条发，老板经常漏看；临时改行程要逐个通知。
- **使用场景：** 在网页后台批量录入老板下周行程 → 自动同步到老板的"提醒"时间线 → 行程变更一键更新并 AI 语音播报给老板。
- **价值：** B 端付费入口（企业版按席位收费）。

#### 🧑‍🎓 画像 C：苏苏，26 岁，独居设计师

- **痛点：** 独居，社交圈窄；外卖快递等位信息零散；深夜想找人说话但不想"打扰"真人朋友。
- **使用场景：** AI 分身陪聊、提醒取快递；在兴趣圈（插画圈）认识同城朋友后转到"对话"单聊。
- **价值：** 高活跃度 + 口碑传播者。

#### 👴 画像 D：王阿姨，63 岁，退休教师（V3 阶段）

- **痛点：** 水电煤缴费忘记、挂号抢号难、子女不在身边。
- **使用场景：** 全程语音："小伴，明天提醒我交电费"；子女远程绑定家庭圈，代她管理账单并收到异常提醒。

## 4. 竞品分析与差异化定位

| 产品                | 它强在哪      | 它的软肋                          | 「伴」怎么打                                    |
| ----------------- | --------- | ----------------------------- | ----------------------------------------- |
| **微信**            | 关系链垄断、生态全 | 臃肿、广告多、永远不会为"个人效率"做深（商业模式不允许） | 不打关系链正面战场，打"重要的少数人 + 个人事务"场景；支持通讯录导入降低冷启动 |
| **豆包/Kimi/文心**    | 大模型能力强、免费 | 无生活数据、无社交、用完即走，是"工具"不是"管家"    | 用"数据聚合 + 主动服务"差异化：它不找你，你找它；「伴」是反过来        |
| **支付宝**           | 账单/缴费数据最全 | 社交失败史、AI 能力弱、工具属性重            | 账单数据通过授权对接为我所用，不正面竞争                      |
| **飞书/钉钉**         | 工作场景垄断    | 生活场景绝缘体                       | 工作事务只做"轻录入+提醒"，不做协同办公                     |
| **苹果提醒/日历/记账App** | 系统级、免费    | 被动记录、无 AI 主动性、无社交             | 它们是"记事本"，「伴」是"秘书"                         |

> **差异化定位总结：** 三个坐标轴上同时占位 —— **通讯简洁度（对标微信做减法）× 生活数据聚合度（对标支付宝做连接）× AI 主动智能度（对标大模型做场景）**。任何单一维度的竞品都无法覆盖这个组合。

## 5. 产品总体架构

### 5.1 信息架构（IA）

底部 5 个 Tab + 全局 AI 悬浮入口（任何页面可唤起）。AI 不是第 5 个 Tab 的附属，而是**贯穿所有模块的中枢**——Tab 5 只是它的"全屏对话形态"。

```
底部导航： 💬 对话 ｜ ⏰ 提醒 ｜ 🌐 圈子 ｜ 👤 我的 ｜ ✨ AI

对话 ── 单聊 / 群聊（文字、语音、图片、位置、文件）
        └─ 会话内 AI 能力：智能总结未读、代拟回复、语音转文字

提醒 ── 今日时间线（聚合视图）
        ├─ 工作事务（秘书后台录入：出差/会议/接待/拜访）
        ├─ 金融账单（信用卡/贷款/水电煤/物业/话费）
        ├─ 消费进度（电商物流/外卖/排队等位/票务）
        ├─ 出行行程（机票/酒店/火车/打车）
        └─ 手动创建 + AI 从对话中自动识别生成

圈子 ── 群空间（基于对话群的动态圈）
        ├─ 朋友圈（纯时间序，无算法、无广告）
        ├─ 兴趣圈（公开主题社区，可发现新朋友）
        └─ 家庭圈（账单共享、远程关怀）

我的 ── 钱包 / 会员订阅 / 设置
        ├─ 通讯录（添加的个人联系人 + 群汇总入口）
        │    ├─ 个人联系人：全部好友列表，字母索引/搜索/标签分组
        │    └─ 群：我加入的所有群汇总显示，按活跃度/置顶排序
        ├─ 账号授权中心（第三方平台授权管理仪表盘）
        ├─ AI 设置（模型选择、人格、声音、记忆管理）
        ├─ 我的画像（AI 生成的多维画像可视化）
        └─ 隐私中心（数据导出、删除、授权撤回）

AI  ── 全屏对话（文字/语音/图片）
        ├─ 默认形态：直接进入与 AI 的日常对话，零门槛开口
        ├─ 角色/场景选择：管家 / 秘书 / 分身 / 树洞 / 私人医生 等
        ├─ 主动服务：每日简报、异常预警、智能建议
        └─ 跨模块调度：一句话创建提醒、发消息、查账单
```

### 5.2 技术架构

```
┌─ 客户端层 ──────────────────────────────────────────────┐
│  iOS / Android（Flutter 跨端） + 网页管理后台（秘书端/React）│
└──────────────────────────┬───────────────────────────────┘
                           │ HTTPS / WSS
┌─ 接入层 ────────────────┴───────────────────────────────┐
│  API 网关 │ 长连接网关（IM） │ 鉴权中心 │ 限流/风控        │
└──────────────────────────┬───────────────────────────────┘
┌─ 业务服务层（微服务）───┴───────────────────────────────┐
│  IM 消息服务   │ 提醒/日程服务 │ 圈子动态服务 │ 钱包服务    │
│  ★数据聚合服务（第三方对接：账单/电商/出行/邮件解析）      │
│  秘书后台服务（企业事务录入 → 同步用户时间线）              │
└──────────────────────────┬───────────────────────────────┘
┌─ AI 中台（核心壁垒）────┴───────────────────────────────┐
│  大模型网关（多模型路由：自研+第三方，可切换）              │
│  ★Agent 编排引擎：意图识别 → 工具调用 → 跨模块执行        │
│  ★用户记忆系统：短期会话记忆 + 长期事实记忆（RAG）         │
│  ★画像引擎：多维标签 + 行为序列 → 用户画像图谱            │
│  主动服务引擎：事件触发 / 定时任务 / 异常检测               │
└──────────────────────────┬───────────────────────────────┘
┌─ 数据层 ────────────────┴───────────────────────────────┐
│  消息库（端到端加密可选）│ 用户数据 Vault（账单/行程，加密） │
│  向量库（记忆/画像）│ 图数据库（关系链+画像图谱）│ 对象存储  │
└──────────────────────────────────────────────────────────┘
```

> **架构要点：**
>
> 1. **AI 中台是独立层**，所有业务服务对它暴露工具接口（Tool API），AI 通过 Agent 编排跨模块调度——这是"AI 是中枢而非功能"在技术上的落点。
> 2. **数据聚合服务与 AI 中台解耦**，第三方对接的脏活累活收敛在一个服务里，便于逐个平台灰度上线。
> 3. **用户敏感数据进 Vault 加密存储**，密钥与画像数据分离，支撑合规承诺。

## 6. 五大模块功能设计

### 6.1 对话 —— 做"三无一有"的纯粹通讯

> **设计原则：无广告、无信息流、无商业入口，有温度。** 只保留"和人在说话"所需要的一切，多一样都不加。

| 功能        | 说明                                   | 优先级           |
| --------- | ------------------------------------ | ------------- |
| 单聊/群聊     | 文字、语音条、图片、位置、文件；语音支持倍速播放与转文字         | **P0**        |
| 语音通话      | 1v1 语音（视频放 P2，克制）                    | P1            |
| 会话分组/折叠   | "重要的人"置顶区，其余自动折叠，信息降噪                | P1            |
| AI 未读总结   | 长按群聊 → AI 总结 99+ 未读为 3 行要点（不读原文也能接话） | **P0 · 差异化**  |
| AI 代拟回复   | 输入框唤起 AI，根据聊天上下文生成语气可选的回复草稿          | P1            |
| 对话内转提醒    | 长按消息 → "设为提醒"（AI 自动提取时间地点事项）         | **P0 · 打通模块** |
| 阅后即焚/定时消息 | 可选的轻隐私功能                             | P2            |

**明确不做：** 朋友圈广告、小程序平台（早期）、视频号/直播、公众号、游戏分发、支付场景补贴大战。**每一个"不做"都是写给用户的承诺书。**

### 6.2 提醒 —— 产品的心脏：全方位"今日时间线"

> **核心理念：从"人记事"到"事找人"。** 所有事项无论来源，统一汇入一条按时间排序的"今日时间线"，AI 负责聚合、排序、提醒、预警冲突。

**事项的四大来源：**

```
① 第三方自动对接 → ② 他人代录（秘书/家人） → ③ AI 从对话/邮件/短信识别 → ④ 用户手动创建 → 统一时间线
```

**场景清单（按对接难度分级）：**

| 类别   | 场景              | 数据来源与对接方式                                            | 优先级    |
| ---- | --------------- | ---------------------------------------------------- | ------ |
| 工作事务 | 出差行程            | 秘书网页后台录入（本产品的 B 端入口）→ 实时同步老板时间线；同时可被航旅/酒店数据自动校验补充    | **P0** |
| 工作事务 | 会议/接待/拜访        | 秘书后台 + 手动创建 + AI 从对话识别（"明天下午三点和张总开会"→ 自动建提醒）         | **P0** |
| 工作事务 | OA/邮箱日历同步       | CalDAV/Exchange/企业微信日历只读同步（V2）                       | P2     |
| 金融账单 | 信用卡还款           | 账单日/还款日：① 银行账单邮件解析（授权邮箱）② 银联云闪付开放接口 ③ 手动录入兜底         | **P0** |
| 金融账单 | 贷款（房贷/车贷/消费贷）   | 手动创建一次 → AI 自动生成每期循环提醒 + 金额变动校验                      | **P0** |
| 金融账单 | 水电煤/物业/话费       | 政务/公共事业缴费平台对接（各地差异大）→ 中期以"缴费提醒模板 + 支付宝/微信缴费记录导入"过渡   | P1     |
| 消费进度 | 电商物流（京东/天猫/拼多多） | ① 官方开放接口/联盟 ② 授权读取发货短信与邮件 ③ 用户转发物流短信给 AI 解析          | P1     |
| 消费进度 | 外卖/排队等位         | 美团/饿了么/美味不用等开放能力有限 → 以"截图给 AI 识别"与"分享卡片到伴"做轻对接       | P2     |
| 消费进度 | 票务（电影/演出/挂号）    | 短信/邮件解析 + 日历文件（.ics）识别                               | P1     |
| 出行行程 | 机票/火车           | 航旅纵横/12306 出票短信与邮件解析（成功率 95%+）→ 自动生成含值机/检票口/晚点预警的行程卡 | **P0** |
| 出行行程 | 酒店（携程等）         | 订单邮件解析；入住当天时间线自动出现"今日入住"卡片含地址导航                      | **P0** |

**时间线的智能能力：**

- **冲突预警：** "周六下午你已答应同学聚会，系统检测到 14:00 有一张三亚航班，是否调整？"
- **链式提醒：** 出差 = 机票 + 酒店 + 报销提醒 + 目的地天气，自动打包成一个"行程集"。
- **异常检测：** 信用卡账单金额环比突增 50% → AI 主动询问是否需要查看明细。
- **免打扰节律：** 23:00–7:00 静默，紧急事项（航班取消）才穿透。

### 6.3 圈子 —— 反算法的社交连接

| 功能          | 说明                            | 设计要点                                    |
| ----------- | ----------------------------- | --------------------------------------- |
| **群空间**     | 每个群自动拥有一个共享空间：群相册、群日程、群文件、群接龙 | 群不只是聊天，是"一个小圈子的共同记忆"，与提醒模块打通（群日程进个人时间线） |
| **朋友圈**     | 纯时间序动态：文字/图片/语音日记             | **无算法推荐、无广告、无点赞排行**；可设"仅本月可见"等轻隐私粒度     |
| **兴趣圈**     | 公开主题社区（徒步/读书/养猫…），可发帖、约活动     | 承担"认识新朋友→沉淀为对话关系"的增长飞轮，是社交冷启动的引擎        |
| **家庭圈**     | 家庭成员共享账单提醒、位置关怀（授权制）、代办指派     | 面向家庭主理人与银发场景的关键抓手（V2–V3）                |
| **AI 在圈子里** | 可 @AI 总结讨论、发起投票、把群聊结论一键变日程    | AI 是圈子的"公共秘书"，强化中枢定位                    |

### 6.4 我的 —— 个人数字资产的总控台

| 板块         | 功能                                                                                         | 备注                                              |
| ---------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------- |
| **通讯录**    | **个人联系人：** 已添加的全部好友，字母索引、搜索、标签分组、星标朋友；**群：** 我加入的所有群在此汇总显示，按置顶/最近活跃排序，支持搜索与批量管理（折叠、退出、免打扰） | 对话模块承载"聊"，通讯录承载"找人与管关系"；群统一汇总一处，避免群聊散落在对话列表淹没单聊 |

| **我的画像**   | AI 基于对话与行为生成的多维画像：**兴趣图谱、消费结构、社交节律、日程密度、情绪曲线、关注领域**，可视化呈现，用户可修正                            | 见第 7 章；支持导出，向用户证明"画像属于你"                        |
| **隐私中心**   | 数据导出（全量打包）、账号注销、端到端加密开关、设备管理                                                               | 合规刚需 + 品牌承诺                                     |
| **通用设置**   | 通知节律、主题、字体（关怀模式大字体为银发铺路）                                                                   | —                                               |


### 6.5 AI —— 中枢：日常对话 + 多角色场景

**默认形态：打开 Tab 5 即直接进入与 AI 的日常对话，零门槛开口**——就像和一个住在你手机里的老朋友聊天，想到什么说什么：问问题、聊心情、交代事情、商量计划。AI 带着完整的个人上下文（画像 + 记忆 + 当日时间线）应答，不需要用户做任何"角色配置"。

**角色/场景选择：** 当用户有明确诉求时，可从对话顶部或输入框旁一键切换角色/场景（也可语音直接说"切到秘书模式"）。角色即"同一 AI 的不同人格与权限包"，切换后对话记忆与画像保持贯通。

**角色矩阵（一套底座，多套人格与权限，可持续扩展）：**

| 角色/场景      | 定位                                            | 典型交互                                |
| ---------- | --------------------------------------------- | ----------------------------------- |
| 🤵 **管家**  | 主动型生活管理：时间线、账单、行程、预警                          | "你明天 7:40 出门才不迟到，我叫车吗？"             |
| 📋 **秘书**  | 执行型：代写、代回、代约、代查，跨 App 操作                      | "帮我把周四下午的会推到周五，并通知参会的三个人"           |
| 🪞 **分身**  | 了解你的一切，能"以你的口吻"起草内容、回答朋友的问题（需你确认才发送）          | "以我的风格回一下这条消息" / 面试前"模拟 HR 问我问题"    |
| 🕳️ **树洞** | 情绪陪伴：不评判、不给建议除非你要，纯倾听（独居与深夜场景）                | "今天好累。" —— "我在，你说。"                 |
| 🩺 **私人医生** | 健康场景：症状咨询与就医建议、体检报告解读、用药/复诊提醒、家人健康档案（接入提醒模块） | "帮我看看这份体检报告哪几项要注意" / "提醒我每天晚上 9 点吃降压药" |

> ⚠️ **私人医生的边界（必须克制）：** 定位为**健康咨询与健康管理助手，非诊疗服务**——不下诊断、不开处方，涉及疾病判断时一律引导就医；界面常驻"咨询仅供参考"提示；健康数据属敏感个人信息，单独授权、独立加密分区存储，**不参与画像推断、永不用于其他场景**。远期若做在线问诊，需另取互联网医院资质，不在 MVP 范围。

**AI 的三类交互形态：**

1. **全屏对话（Tab 5）：** 文字/语音/图片多模态，支持连续任务（"帮我规划下周杭州出差"→ 查票 → 比价 → 建行程 → 问你确认）。
2. **全局悬浮球：** 任何页面唤起，承接"当下语境"——在对话页唤起即带着聊天记录，在提醒页唤起即带着当日时间线。
3. **主动服务卡片：** AI 不等用户开口，在提醒页顶部、对话页顶部推送每日简报与预警（频率克制，宁缺毋滥）。

## 7. AI 中台与用户画像体系

### 7.1 数据飞轮（产品最核心的增长引擎）

```
用户行为与授权数据 → 记忆系统（事实+偏好） → 多维画像 → 更准的主动服务 → 更多使用与授权 ↺
```

飞轮一旦转动，**迁移成本随时间线性增长**——用户用了 18 个月的 AI 管家，比微信的关系链更难离开，因为微信记录的是"你认识谁"，「伴」记录的是"你是谁"。

### 7.2 画像维度设计（"我的"模块可视化呈现）

| 维度          | 内容                                            |
| ----------- | --------------------------------------------- |
| 🎯 **兴趣图谱** | 从对话与圈子中提取的兴趣标签云（如：徒步/手冲咖啡/科幻），标注置信度与时间衰减      |
| 💳 **消费结构** | 聚合账单数据生成月度消费画像：餐饮/出行/数码占比、消费节律、冲动指数           |
| 🤝 **社交图谱** | 亲密度分层（家人/密友/同事/弱连接）、响应模式、社交能量曲线（何时爱聊天）        |
| 📅 **时间画像** | 日程密度热力图、通勤规律、差旅频率 → 支撑"何时提醒最合适"               |
| 🌊 **情绪曲线** | 基于对话语义的周/月情绪波动（仅端内可见，绝不用于广告），异常低谷时树洞角色主动关怀    |
| 🧠 **偏好档案** | AI 记住的事实清单："不吃香菜""喜欢靠窗座位""周三晚上打球"——逐条可见、可改、可删 |

> 🚫 **画像的三条铁律（写进产品宪法）：**
>
> 1. 画像**只对用户本人可见与可用**，不向任何第三方出售、不用于广告定向；
> 2. 每个画像结论都支持"查看依据 + 一键修正/删除"；
> 3. 敏感维度（健康、政治、宗教）**永不推断**。
>
> 违背任何一条，产品的信任根基即告崩塌。

### 7.3 记忆系统分层


| 层    | 内容                    | 存储与生命周期         |
| ---- | --------------------- | --------------- |
| 会话记忆 | 当前对话上下文               | 会话结束即压缩归档       |
| 事实记忆 | 用户明确告知的事实（生日、忌口、车牌号）  | 向量库长期存储，用户可逐条管理 |
| 行为记忆 | 行为序列归纳的模式（每周五加班、月初还贷） | 定期重算，置信度随样本更新   |
| 画像层  | 由上述记忆聚合出的多维标签图谱       | 图数据库，支持解释与回溯    |

## 8. 第三方数据对接策略（最难也最值钱的部分）

提醒模块的成败取决于数据接入的广度与稳定性。现实是：大厂不会为一个新产品开放核心接口。因此采用**三层递进策略**，同一数据源能直连则直连，不能直连走授权，都不行用解析兜底：

| 层级          | 方式                                         | 适用场景                           | 成本/风险                                       |
| ----------- | ------------------------------------------ | ------------------------------ | ------------------------------------------- |
| **L1 官方直连** | 开放平台 API、商务合作                              | 航旅类、部分公共事业缴费、企业 OA             | 慢，需要 BD 逐个谈；最稳定                             |
| **L2 用户授权** | OAuth 授权、邮箱授权读取（IMAP/Gmail API）、.ics 日历订阅  | 账单邮件（银行出账单 100% 发邮件）、酒店/机票确认邮件 | 合规路径清晰；覆盖率取决于用户授权率，需把"授权收益"讲透               |
| **L3 智能解析** | AI 解析用户转发/截图的短信、订单页、聊天消息（端侧 OCR + LLM 结构化） | 物流短信、外卖截图、等位页面、任何长尾来源          | **这是大模型时代的杀手锏**：不用谈任何商务，覆盖一切数据源；用户一键转发即完成对接 |

> **战略判断：** L3 是本产品冷启动的关键路径——AI 解析能力让"对接京东携程"这个原本需要百人 BD 团队的事，变成"用户把短信转发给 AI"的产品功能。L1/L2 随规模逐步补上提升自动化率。**第一期聚焦：银行账单邮件 + 航旅酒店确认邮件 + 短信转发解析**，三个就能覆盖 80% 高频提醒场景。

## 9. 商业模式

### 💎 C 端订阅（主收入）

- **免费版：** 完整通讯 + 基础提醒（手动+解析）+ AI 每日 20 轮对话
- **Pro ¥25/月：** 无限 AI、第三方自动对接（L1/L2）、AI 未读总结、画像报告、主动服务全量
- **Pro+ ¥45/月：** 分身角色、声音克隆、家庭共享（最多 5 人）、专属模型通道

### 🏢 B 端秘书版 SaaS（第二曲线）

- 企业行政/秘书后台：高管时间线管理、接待安排、差旅同步
- 按席位收费（如 ¥99/秘书/月，高管免费绑定）
- 天然获客路径：秘书录入 → 老板装 App → 老板全家/朋友扩散

### 🧩 增值与生态（远期）

- 云存储扩容、专属声音/形象、AI 技能市场（第三方 Agent 上架分成）
- 缴费代办抽佣（水电煤代缴通道）

### 🚫 明确不做的收入

- **不做广告** —— 这是与微信差异的品牌根基，写入产品宪法
- **不卖数据** —— 画像数据的商业化即信任破产
- **不做金融放贷导流** —— 账单数据毗邻金融，诱惑大，必须克制

## 10. 合规与隐私

| 合规项       | 要求                 | 落地动作                                  |
| --------- | ------------------ | ------------------------------------- |
| 生成式 AI 备案 | 《生成式人工智能服务管理暂行办法》  | 上线前完成算法备案与安全评估；接入第三方模型也需履行备案义务        |
| 个人信息保护    | 《个保法》：敏感个人信息单独同意   | 账单/行程属敏感信息，逐项授权、可撤回；授权中心实时可查          |
| 数据安全      | 《数据安全法》分级分类        | 用户 Vault 加密存储、密钥分离、境内存储               |
| IM 内容安全   | 即时通讯内容合规义务         | 文本/图片/语音审核体系（机审+人审）；端到端加密会话的合规方案需专项设计 |
| 金融数据边界    | 账单数据不得用于信贷导流等未授权用途 | 数据用途白名单制，写进隐私政策的醒目位置                  |
| 未成年人      | 未成年人模式             | AI 对话内容过滤、时长限制、树洞角色未成年人专项安全策略         |
| 健康咨询边界    | 私人医生角色不得构成诊疗行为（《互联网诊疗监管细则》） | 仅提供健康咨询与信息参考，不下诊断、不开处方、引导就医；健康数据单独授权、独立加密分区，与画像系统物理隔离；远期在线问诊需取得互联网医院资质 |

## 12. 风险与挑战

| 风险                          | 等级   | 应对策略                                                                  |
| --------------------------- | ---- | --------------------------------------------------------------------- |
| **微信降维打击**（微信推出 AI 管家/智能总结） | 🔴 高 | 微信的商业模型（广告+流量分发）决定它无法承诺"无广告、不卖数据"；我们拼的是"克制"这张牌，大厂抄不动。同时快速积累画像数据形成迁移成本 |
| **第三方数据对接受阻**（接口不开放、解析被对抗）  | 🔴 高 | 三层策略兜底（第 8 章）；L3 用户主动转发路径不可被封锁，保证体验下限                                 |
| **AI 推理成本失控**               | 🟡 中 | 多模型路由（简单意图走小模型/端侧模型）；订阅制天然对冲成本；主动服务做频率预算                              |
| **隐私安全事故**（一次即致命）           | 🔴 高 | Vault 加密+密钥分离；画像端侧优先计算；安全投入前置，不等出事再补                                  |
| **监管变化**（AI 备案、IM 内容责任收紧）   | 🟡 中 | 合规先行（第 10 章）；保留"通讯可独立运营"的降级方案                                         |
| **社交冷启动失败**（没有朋友在用，对话模块空转）  | 🟡 中 | 接受它——前期对话服务"管家用户间的小圈层"而非全民关系链；兴趣圈承担增量连接                               |

---

> **最终判断：** 这个产品真正在赌的是一件事 —— **AI 时代的"微信"不会是微信自己长出来的**。微信的组织基因决定它做不出一个"克制、无广告、为你个人服务"的产品。窗口期大约 2–3 年，拼的是谁先让 1000 万用户的 AI"离不开自己的生活数据"。建议以"AI 时间线管家"为楔子单点切入，社交做留存，画像做壁垒。
